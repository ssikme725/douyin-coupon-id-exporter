# 抖店优惠券商品 ID 导出

一个本地 Edge/Chrome 扩展。在已登录的抖店优惠券详情页点击“导出 Excel”，即可把“指定商品（商品券）”里的商品 ID 导出为 `.xlsx`。19 位商品 ID 在表格中保存为文本，不会因 Excel 数字精度限制而改变。

## 安装与使用

见 [使用说明.md](使用说明.md)。

## 工作方式

- 只在用户点击扩展按钮时读取当前标签页。
- 在抖店页面内请求当前优惠券的详情接口，读取 `type_detail` 里的 `product_id`。
- 将详情返回数量与页面的“已选数量”核对。数量不一致或详情未带商品时，调用抖店页面自身使用的 `get_coupon_scope` 分页接口，按每页 20 条连续读取；不设 500 条上限。
- 核对分页总数、每页条数及记录唯一性，完成后复核第一页。漏页、重复页、超时或数量变化会报错，不生成不完整文件。同一商品的不同渠道记录核对完整后，商品 ID 去重导出。
- 在浏览器本地生成并下载 Excel；不向其他网站上传商品数据。
- 只申请 `activeTab` 和 `scripting` 权限。

本工具适用于当前抖店页面结构。若抖店更改接口，可能需要更新解析逻辑。

## 开发测试

使用 Node.js 运行以下测试。测试使用虚构商品 ID，不包含店铺数据：

```sh
node test.mjs
node scope-reader.test.mjs
node popup.test.mjs
```

覆盖 500、501、1000/1001、4041、5000 条虚构商品、长 ID 文本精度、接口截断后的补取、渠道去重、分页失败时禁止下载。

## 1.1.0 修复说明

实店排查确认：大券详情接口的 `type_detail` 只返回前 500 个商品；页面自身通过 `get_coupon_scope?page=...&size=...&coupon_meta_id=...` 获取完整商品范围。旧版只读取一次详情接口，没有数量核对或补取路径，所以遗漏第 501 个及之后的商品。Excel 写入本身没有 500 条限制。

新版增加完整分页读取，并兼容结构化明细及 JSON 中未加引号的长整数 ID。读取期间请保持扩展弹窗打开，不要切换或修改优惠券。请求使用当前页面已有登录态，无需复制 Cookie、Token 或签名。

分页协议和 500 条截断已用实际页面请求确认；自动测试仅包含虚构数据。页面及接口将来变化时，需要再次核对响应结构。
